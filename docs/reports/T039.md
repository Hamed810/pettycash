## Verification Details

### SubmitSheet Implementation
| Feature | Implementation |
|---------|----------------|
| Atomic submission | `TransactionManager::transactional()` |
| Idempotency | `IdempotencyService::execute()` with command ID |
| Validation | Owner check, version check, open status, transaction completeness |
| Cost center routing | Validates cost center exists via `CostCenterRepository` |
| Domain submission | `ExpenseSheet::submit()` - snapshots total, sets status to CostCenter |
| Audit event | Creates `AuditEvent` with SUBMISSION type, snapshots before/after |
| Persistence | Saves sheet via `ExpenseSheetRepository` |

### Compliance with Requirements
| Requirement | Implementation |
|-------------|----------------|
| Atomic submission (FR-042) | Single database transaction |
| Idempotency (FR-018) | Command ID replay via `IdempotencyService` |
| Cost center routing (FR-032) | Validates cost center, will route to manager queue |
| Audit on submission (FR-051) | SUBMISSION event with actor snapshot, before/after |
| Balance-independent (FR-027) | No balance check before submission |

### Architecture Compliance
- Service in **Application/Workflow** layer
- Uses **Application Ports** (TransactionManager, CurrentUser, repositories, IdempotencyService)
- Domain logic in `ExpenseSheet::submit()`
- Audit via `AuditWriter` port
- No controllers or HTTP concerns
