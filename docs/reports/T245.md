# T245 — Restore the frontend type gate

**Status**: Complete for its stated scope

## Task

Bring `npm run typecheck` back to zero errors so the `npm run check` gate mandated by `AGENTS.md`
can pass end to end, by reconciling the RED spec's prop/fixture contract with the component prop
contracts produced by T181. Explicitly **not** to be closed by loosening `tsconfig.json` strictness,
suppressing the suites, or excluding them from the typecheck project.

## Which side was wrong

`src/types/api.ts` and `contracts/ocs-api.yaml` **agree** with each other. The RED spec disagreed with
both, so the spec was corrected. Nothing in `tsconfig.json` was touched, neither suite was
suppressed, and both remain in the typecheck project.

| Error | Was | Became |
|---|---|---|
| 11 × | `ownerId` on a queue item | `TransactionSummary`: `sheetId`, `activeRevision`, `finalOutcome`, `evidenceCount`, `version` |
| 5 × | `latestDecision` missing | added; it is required by the contract |
| 3 × | `actorName` / `actorRole` / `createdAt` | `actor: { userId, displayName, role }` + `decidedAt` |
| 2 × | `{ uid, roles, costCenterCodes }` | `User` is `{ userId, displayName, roles }` |
| 4 × | `DecisionForm` mounted without `allowedActions` | required prop now supplied |
| 1 × | `fileName`, missing evidence fields | `name`, plus the required `transactionId`/`revisionId`/`uploadedBy` |
| 2 × | unused `id` on stubbed `accountById` | `_id` |

## One deletion worth justifying

The senior-queue fixtures carried a `priorDecisions` array. It was removed because it is **not** in
the contract's `TransactionSummary` and `SeniorQueueView` reads `item.latestDecision` — nothing ever
consumed it. The test that asserts advisory cost-center visibility still passes its data through
`latestDecision`, which is what the component actually renders.

## `npm run check` still does not pass end to end — and that is correct

`npm run test` reports the **same** 58 failed / 18 passed / 26 errors as before this change, byte for
byte. Those suites are RED by construction: they assert US2 review behaviour that is not implemented
yet, and one is literally titled `Management Review - Vue Component Tests (RED: behavior not
implemented)`.

T245's own wording asks for the spec/prop reconciliation and the two `PurchaserFlow.spec.ts` errors,
and that is what was delivered. The gate closes when the corresponding implementation lands — not by
making a RED suite pass early, which would be the "loosening" the task forbids. No test was skipped,
marked `it.skip`, or deleted to get there.

## A larger divergence this uncovered, deliberately not fixed here

`ReviewController::formatTransaction()` returns `revision`, `ownerId`, `costCenterId`,
`expenseTypeTitle`, and `hasEvidence`. The contract's `TransactionDetail` requires `activeRevision`,
`latestDecision`, `evidenceCount`, `allowedActions`, `decisions`, and `evidence` — and the server
returns **none** of those. So the API does not currently implement the contract it is typed against,
and `PriorDecisionHistory` cannot be fed from a live response because no `decisions` array is ever
returned.

That is a real contract-conformance defect, but it is not a typecheck error and fixing it means
changing response shapes across the backend — far outside T245. It is recorded for the next
convergence pass rather than smuggled in here.
