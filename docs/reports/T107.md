## Why this task was sequenced ahead of the US5 configuration slice

`lib/Application/Configuration/` and all five US5 services are absent, and T081 is the first genuinely
incomplete task in dependency order. It was not taken first because **FR-017 requires every sensitive
configuration change to write a configuration audit event, and the only audit surface that exists writes
to the transaction table.** `AuditWriterService::append()` targets `pettycash_transaction_audit`
unconditionally, so any configuration service built now would record its audit events in the wrong
stream — the CRITICAL defect T294 owns, which is itself gated on T253's naming decision. Building T081
first would produce a service whose audit trail is knowingly misrouted.

T107 has no such entanglement: a leaf adapter behind the existing `Exporter` port, no audit, no role
scoping, and `contracts/exports.md` specifies its behaviour precisely. It could be built and verified
end to end, which is what it was.

## The decision the whole class turns on

The contract requires "spreadsheet cells beginning with formula control characters are escaped" and
"CSV opens without formula execution from user-controlled text". The standard hardening advice is to
prefix any cell starting with `=`, `+`, `-` or `@` with an apostrophe.

**Applied naively to a report of petty-cash amounts, that advice corrupts the data.** `-1234.56`
becomes `'-1234.56` — a negative return rendered as text. A financial export that mangles its own
numbers is a worse outcome than no export, and the defect would only surface once a cost centre
actually returned money, months after the exporter was written.

So escaping keys on the **PHP type**, not the string:

- `int` / `float` → always written plainly, never escaped
- `string` → escaped when it begins with `=`, `+`, `-`, `@`, tab, or CR
- `null` → empty cell; `bool` → `true`/`false`; `DateTimeInterface` → ISO 8601

The cost is a rule for callers — **pass numbers as numbers, not as numeric strings** — and it is stated
in the class docblock. The benefit is that the case hardening actually exists for is covered: a
description, cost-centre name, or explanation a user typed.

Both directions are asserted, and each is needed. `testANegativeAmountIsNotFormulaEscaped` fails if
escaping overfires; `testAUserSuppliedStringIsFormulaEscaped` (8 data sets, including
`=HYPERLINK("http://evil","click")` and the `=cmd|"/C calc"!A0` leet form) fails if it underfires. A
gate written either way passes half the suite.

## Three defects found while writing the tests

**1. In the exporter — a real bug the test caught.** The header union used
`array_merge($header, array_keys($row))`, and `array_merge` does **not** deduplicate integer-keyed
values. Two rows sharing a column produced the header `a,b,a` and a record with a trailing cell per
repeated key — a structurally valid CSV that silently duplicates every shared column. Fixed with an
explicit first-seen-order dedupe.

**2. In my own test — an index that measured nothing.** The parse helper read `$records[1][1]`, written
for a multi-column row. These rows carry exactly one column, so the value is at `[0]` and the helper
returned `''` for every case. Six assertions were "failing" for a reason that had nothing to do with the
exporter. Worth stating plainly: a helper that returns empty for all inputs is not a test helper, and
the correct response was to fix the helper rather than to relax the assertion.

**3. An assertion that was backwards.** The escaped value comes back from a CSV reader as
`'` + input, because the apostrophe is a literal character in the field that the *spreadsheet
application* strips on import. The test demanded the value be unchanged, which would have asserted that
the escape did nothing.

## RFC 4180, and a deprecation that is really a compatibility warning

`fputcsv` still defaults `$escape` to a backslash, but PHP has deprecated that default and **will change
it**. A backslash is a spreadsheet convenience, not part of CSV. The exporter writes with
`escape: ''` and an explicit `"\n"` line ending, so the file is RFC 4180 and any future reader parses it
with its own defaults — a report consumed by a script in another language should not need to know
anything about this application.

This was found by the test emitting a `fgetcsv(): the $escape parameter must be provided` deprecation,
not by reading a changelog.
