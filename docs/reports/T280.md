# T280 — Make the transaction OCS payload conform to its own contract

**Status**: Complete

## Task

`contracts/ocs-api.yaml` defines `TransactionSummary` and `TransactionDetail`. The backend answered
a different shape, and the frontend is written to the contract — so the review and transaction views
could not render at all.

## The real shape of the problem

`src/views/reviews/CostCenterQueueView.vue:59-60`, `SeniorQueueView.vue:59-60`, and
`SheetDetailView.vue:194-197` all read:

```js
item.activeRevision.costCenter.name
item.activeRevision.expenseType.name
item.activeRevision.amount
```

The server never sent `activeRevision`. Every one of those templates dereferenced `undefined` on
every live response. Because `decisions` was also never returned, `PriorDecisionHistory.vue` had
nothing to render even though the component and its props were complete — which is why the US2
advisory-decision journey in T054 could not be built on a working endpoint.

The unit and integration suites could not catch this: `tests/bootstrap.php` wires in-memory
doubles, and the contract tests asserted the OCS envelope and status code rather than the payload
shape. **A green suite was compatible with every view being broken.**

## The duplication was the root cause

`TransactionController` and `ReviewController` each carried a private `formatTransaction()`, and the
two copies had drifted *from each other* as well as from the contract. Leaving the formatting
duplicated would have let it drift again, so the fix was to centralise it:

`lib/Infrastructure/Http/TransactionPayloadFormatter.php` is now the single source:

| Method | Contract schema | Used by |
|---|---|---|
| `summary()` | `TransactionSummary` | queue and list responses |
| `detail()` | `TransactionDetail` | single-transaction responses |
| `revision()` | `Revision` | `POST /correction`, `GET /revisions` |
| `allowedActions()` | `CapabilitySet` | inside `detail()` |

## Two tables deleted

`TransactionController::CURRENCY_MINOR_UNITS` and `ReviewController::getMinorUnit()` had no other
reader once the formatters were replaced, so `minorUnit` now comes from the configured
`Currency.minor_unit` through `CurrencyRepository`. That covers most of what T266 asks for; T266
stays **open** for the part deliberately not done here — turning an unknown or inactive currency into
an explicit error rather than a zero-digit fallback.

## `allowedActions` is derived from the real authorization decision

The capability set is computed from the same `AuthorizationService` decision and the actor's real
role assignments that the command path enforces, so a hidden action and a refused action cannot
disagree. This means the T257 scope fix is now visible to the interface rather than only to the
server.

## Correction to the recorded evidence

The convergence task claimed **both** controllers emit the scalar `costCenterId`/`expenseTypeTitle`.
That was only true of `ReviewController`. `TransactionController` already emitted `EntitySnapshot`
objects; its drift was the `revision`-versus-`activeRevision` key, the undeclared `ownerId`, and the
missing `latestDecision`/`evidenceCount`/`allowedActions`/`decisions`/`evidence`. The task text is
corrected in place.

## Tests

Three tests that asserted the old flat shape were updated to the contract path rather than left
passing against a shape the contract does not describe — two from T256, plus T255's
`testDecisionDoesNotEraseTheRevisionBusinessFields`.

Two new live contract tests:

- `testTransactionDetailCarriesTheContractShape` — requires every declared member and **forbids**
  the four undeclared flat shapes, so the drift cannot silently return.
- `testQueueReturnsTransactionSummaryItems` — requires `activeRevision`/`evidenceCount` and forbids
  `decisions`, keeping the two response kinds from being conflated again.
