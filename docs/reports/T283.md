## The two findings that mattered most

**`EvidenceList.vue` rendered nothing.** It used `NcListItem`'s `avatar` / `title` / `subtitle`
slots; `@nextcloud/vue` 9.x has `icon` / `name` / `subname` / `details` / `indicator` / `actions`. So
every evidence row was an empty shell — a purchaser saw no file name, type, size, upload time, state
or action for a transaction's receipt. Correcting the slot names alone would not have been enough:
`NcListItem` also always renders its row as an anchor (a focusable link to `#` for a file that
navigates nowhere) and hides actions behind a hover menu, so FR-058's removal affordance appeared
only when the pointer happened to be over the row. It is now a plain list with always-visible actions.

**Money was divided by a hard-coded 100 in four views.** `Money` carries the currency's own
`minorUnit`; a rial amount was printed one hundred times too small, in the figure a finance officer
reconciles against. `CostCenterQueueView` already had the correct code inline, so the fix existed and
three views had not been brought onto it. It now lives in `src/utils/money.ts`.

## RED validity

Each slice was run against its own pre-slice source. Every failure was on a behavioural claim; none
on a missing attribute the slice had just added, a harness crash, or a skipped test. Two tests
initially failed for the wrong reason and were fixed before being counted (one submitted through a
`data-test` the slice had added; one passed vacuously because its fixture reused the identifiers the
old view hard-coded). The money-scale assertion was additionally mutation-checked: reverting the
shared helper's divisor to `100` fails it on its own.

**Honest caveat on the last slice:** 15 of its 26 tests pass against the pre-slice source, because
`SheetDetailView`'s submission gating and the first slice's FR-027 balance handling were already
correct and only the tests were fictional. They are kept as guards on behaviour that is now asserted
rather than assumed.
