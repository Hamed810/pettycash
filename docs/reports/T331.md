# T331 — The dashboard's figures were reachable, and rendered as a JSON blob

**Status:** complete
**Date:** 2026-10-04
**Phase:** 55 — Convergence (seventeen wire-level gaps between the contract, the server, and the client)

## The defect

`DashboardController::card()` answers each role bucket as an **envelope**:

```php
// lib/Controller/DashboardController.php:152-164
return [
    'userId'           => $uid,
    'figures'          => $figures,      // openSheets, returnedToMe, awaitingReview, …
    'figuresBoundedBy' => self::BOUND,   // 100
    'figuresTruncated' => …,
];
```

`dashboardMetrics()` walked **only the top level** of a bucket. `figures` is an object, so it fell
through to the last branch:

```ts
// src/utils/dashboard.ts:52, before this task
return { key, kind: 'raw', text: JSON.stringify(value) }
```

and `DashboardCard.vue` printed `metric.text` verbatim.

**So each role card rendered four rows, and none of them was a figure:** the `userId`, a monospace
`{"openSheets":2,"returnedToMe":1}` labelled *figures*, `figuresBoundedBy` formatted as the count
**100**, and `figuresTruncated` as yes/no. FR-061's content — open sheets, returned transactions,
review queues, decision counts, balances, movements, administrative summaries — appeared as **none** of
those.

Three consequences, all of them real:

1. **No FR-061 figure was reachable.** US7/AC1's acceptance scenario is that a user sees their roles'
   figures. A user saw a JSON string.
2. **The bound was the largest number on the card.** `figuresBoundedBy` is 100 on every card, and a
   real queue of 4 rendered beneath it at the same `font-size: var(--font-size-emphasis)` and
   `font-weight: 600`. The card's headline number was a caveat.
3. **The empty state was unreachable.** `hasMetrics` is `cards.some(card => card.metrics.length > 0)`,
   and the `userId` row alone satisfied it on **every** bucket the server can emit — so a role holding
   no work could never say so.

## The decision this task required me to make and state

The task text: *"Both sides may need a decision, and it is not the implementer's to make silently…
Pick one and say so in the report."*

**Chosen: flatten one level in `dashboardMetrics`. The wire shape is unchanged.**

The server was already correct, and its nesting is deliberate. Four reasons, each verified rather than
assumed:

1. **The envelope is a unit.** `figures` + `figuresBoundedBy` + `figuresTruncated` exist *together* —
   the class docblock is titled "Figures are bounded, and say so". Hoisting the figures to the card's
   top level would leave `figuresBoundedBy` bounding nothing at that level, which is incoherent.
2. **The nested shape is pinned by contract tests that pass.**
   `tests/Contract/Controller/DashboardControllerTest.php:142-178` asserts `figures` is present,
   `figuresBoundedBy === 100`, `figuresTruncated` is a bool, and every figure is an int.
   Hoisting breaks two of those four assertions, so the "smaller consumer change" is not the cheaper one.
3. **The contract neither endorses nor forbids the nesting.** `Dashboard`'s five role objects are
   `additionalProperties: true` with no inner properties named
   (`specs/001-pettycash-v1-core/contracts/ocs-api.yaml:969-976`). Nothing requires a change on either
   side, so the side that was not wrong does not move.
4. **The task's own acceptance criteria are client-side and name the input shape** — "a card built from
   a **server-shaped** bucket". The client is expected to consume what the server sends.

T328 and T330 are the same shape of decision: the server was right, the client was reading a shape it
wished for. This is now the third instance in Phase 55, which is itself worth recording — the frontend
suite was not capable of disagreeing with the server, because it never saw the server.

## Changes

### Derivation — `src/utils/dashboard.ts`

- `DASHBOARD_FIGURES_KEY = 'figures'` and `DASHBOARD_NOTE_KEYS = ['userId', 'figuresBoundedBy', 'figuresTruncated']`,
  both read off the controller rather than guessed.
- `dashboardMetrics()` now **unwraps `figures` in place, one level**, and routes the three note keys
  out. The value inside `figures` is classified by the *same* `metric()` the top level uses, so a money
  figure keeps its currency instead of being coerced into a count that would print it 100× too small —
  asserted by a test, because "flatten one level" must not mean "coerce whatever is one level down".
  A `figures` that is not a record is **not** unwrapped: it stays visible as whatever it is rather
  than vanishing.
- New `dashboardNotes()` returns the envelope. Split as a separate function rather than a flag inside
  `dashboardMetrics` **on purpose**: a caveat that is merely flagged can be reclassified by a later
  change, whereas one that lives in a different list cannot drift back into the figures.
- The per-value classification was extracted verbatim into a private `metric()` so the two derivations
  cannot diverge. `isMoney` still runs before the scalar branches — a `Money` is an object and would
  otherwise reach the `raw` branch.
- `kind: 'raw'` is **kept**, not removed. It is the honest "this client has no renderer for this"
  branch, an existing test covers it, and a structured value silently discarded is the failure mode it
  exists to prevent.

### Types — `src/types/dashboard.ts`

`DashboardNote = DashboardMetric` and `DashboardCard` gains `notes`. Notes carry the same value-type
discrimination (the bound is a number, the flag a boolean) but not the headline treatment — the
difference is which list the card renders them in, so it cannot be lost in a type.

### Card — `src/components/dashboard/DashboardCard.vue`

Optional `notes` prop, rendered as a `<footer>` under the figures at the floor size and normal weight,
separated by a rule. `metricText()` is reused, so `figuresTruncated` resolves through the catalog
instead of printing `true`/`false`. Labels come from `dashboard.note.<key>` rather than
`dashboard.metric.<key>`, so T119 can name a caveat as something other than a figure.

### Store — `src/stores/dashboard.ts`

Cards carry `notes`. `hasMetrics` needed no logic change — it reads `card.metrics`, which is now figures
only — but its docblock said why, because "metrics" here previously meant "the whole bucket".

### View — `src/views/DashboardView.vue`

Passes `:notes` through.

## A fixture was hiding this

`Dashboard.spec.ts` fed the client a hand-written **flat** bucket:

```ts
purchaser: { openSheets: 2, returnedTransactions: 1 },
costCenter: { queueItems: 7, decisions: 3 },
finance: { queueItems: 9, balance: { amountMinor: 1250000, … } },
admin: { activeUsers: 12 }
```

Every one of those keys is a key **the server never sends**. `queueItems`, `decisions`,
`returnedTransactions`, `activeUsers` do not exist in `DashboardController` or `DashboardQuery`; the
server sends `awaitingReview`, `returnedToMe`, `openSheets`, and the three
`administrativeSummary()` counts. The suite was green against a shape of the client's own invention,
which is exactly the trap Phase 55's preamble names for T327.

**The fixture is the server's shape now**, with a comment naming the controller lines and the contract
test that pins them. One consequence worth naming: swapping the fixture broke the pre-existing
`'renders one card per bucket the projection sent'` test, which asserted on `queueItems`. That test was
asserting on a key the server never sends; it now asserts `awaitingReview`. It was part of the same
defect, not a regression.

## Known limitations

- **`figuresBoundedBy` is still 100, and it is still a window size.** This task made the card *say* so
  honestly; it did not make the figures exact. The repository read behind each figure is paged and no
  domain repository has a count query, which `DashboardController`'s docblock already records. Making
  them true totals is a server change no task owns.
- **FR-061's balances and movements still do not appear.** `figures()` computes queue and sheet counts;
  it never reads an account balance or a movement. That is T106's projection content and a different
  defect. This task makes every figure the server *does* send render as a figure; it does not add
  figures the server does not send.
- **No catalog entry names a `dashboard.note.*` or `dashboard.metric.*` key.** `t()` returns the key,
  so a Persian user sees `openSheets` and `dashboard.note.figuresBoundedBy` as literal identifiers. That
  is T119's catalog, and the components fall back to the canonical key by design rather than inventing
  an English word.
- **The `hasMetrics` empty state is now reachable, but nothing consumes it.** It is a store getter with
  no reader in `DashboardView.vue`. The *card's* own empty state is reachable and tested; this getter
  remains unused, which is T113/T115/T118 territory.
