## Recorded deviation (T226)

T226 as written said to *"change `findByTransactionId(int …)` to accept the `string` UUID identifiers
defined by `data-model.md`, and update the port interfaces"*. **That wording misread the model.**

`data-model.md` line 8 states:

> Every externally addressable aggregate uses an immutable UUID `public_id`; numeric `id` values
> remain internal join keys.

So `findByTransactionId(int $transactionId)` is **correct as originally written** — it targets the
internal `transaction_id` join key, and the migration declares that column `BIGINT unsigned`.
The defect was in the **controller**, which passed an external UUID to an internal-join-key method.

The signature change was implemented, then reverted once `data-model.md` was consulted. The fix was
applied at the correct layer instead: `TransactionController::revisions()` and `::audit()` now resolve
the public UUID through `TransactionService::getTransaction()` and pass `$transaction->dbId`.

Per the governance rule in `constitution.md` ("When artifacts conflict, work MUST stop long enough to
reconcile the conflict in the authoritative artifact rather than choosing silently"), the authoritative
artifact was treated as decisive and the task text was not followed literally.

`tests/Integration/Workflow/ManagementDecisionTest.php:488` passes an int, which remains correct under
this design; it was restored after the revert.

   `DbAuditEventRepository::findBySheetId(int)` still take internal ids. Both are correct under

   LSP error: `Cannot access private property TransactionRevision::$expenseDate`. Pre-dates this cycle
