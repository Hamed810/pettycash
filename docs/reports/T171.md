## What was wrong, and how each was established

The note T171 carried said the suite "fails later and for a different reason: `sheet-list-item` does not
appear after the create form is submitted". That was a symptom. The cause was a **400 with an empty
body**, and the empty body is why the app showed the user a *network error* for a client-side fault.

### 1. `NcSelect` wrote the whole option object into `v-model` — every select, app-wide

`NcSelect` forwards `update:modelValue` verbatim to `vue-select`, whose `reduce` prop defaults to
`option => option`. The app passes `{ label, value }` option objects everywhere, so the **entire object**
landed in whatever `v-model` was bound to. Captured from the browser:

```
POST 400 http://localhost:8080/ocs/v2.php/apps/pettycash/api/v1/sheets
    content-type: application/json
    request body: {"title":"Probe Sheet From Browser",
                   "accountId":{"label":"IRR ۱٬۰۰۰٬۰۰۰٬۰۰۰","value":"e2e00000-0000-4000-8000-000000000004"}}
    response body: <empty>
```

`SheetController::create(?string $title, ?string $accountId)` then raised, from
`data/nextcloud.log`:

```
TypeError: OCA\PettyCash\Controller\SheetController::create():
  Argument #2 ($accountId) must be of type ?string, array given
```

The AppFramework turned that `TypeError` into a 400 whose body is not an OCS envelope, so
`src/services/http.ts:60` — correctly refusing to dereference it — classified it as `NETWORK_FAILURE`.
The declared type of `modelValue` is `string | number`, so no template, store or type-checker objected.
The mismatch existed only at runtime.

**Scope: seven call sites, not one.** Sheet account, transaction cost centre, transaction expense type,
review decision, report period, export format, revision selector. So no review decision and no report
filter could be recorded either. Fixed through `src/utils/selectOption.ts` (`:reduce` + `:get-option-key`),
applied at all seven.

After the fix, same journey:

```
POST 201 .../api/v1/sheets
    request body: {"title":"Probe Sheet From Browser","accountId":"e2e00000-0000-4000-8000-000000000004"}
```

### 2. `NcNoteCard` has no `header` slot — 11 blocks dropped, the purchaser's action bar invisible

`@nextcloud/vue` 9.12.0's `NcNoteCard` declares **only** `default` and `icon`:

```
$ grep -A 4 "slots: Readonly" node_modules/@nextcloud/vue/dist/components/NcNoteCard/NcNoteCard.vue.d.ts
    slots: Readonly<{
        /** The main content (overwrites the `text` prop) */
        default?: Slot;
        /** Manually provided icon */
        icon?: Slot;
    }>
```

Its render is `icon` → `div` → `p.notecard__heading` (the `heading` **string prop**) → `default`. A
`<template #header>` is therefore **dropped without a warning**, and everything inside it disappears from
the page while remaining in the source.

Eleven sites were affected. In `SheetDetailView` — the one view a purchaser must pass through — the
dropped block held **Edit, Add transaction and Submit**. The view still rendered its status chip, its
totals, its transaction table and its audit table, so it looked healthy.

Fixed app-wide: text-only headers use `:heading`; headers carrying interactive content became a
`.card-header-row` child of the card's default slot. A **duplicate** `create-transaction-btn` (it was on
two cards in `SheetDetailView`, making the hook ambiguous) was also removed.

### 3. The app's lower half was unreachable — `#content` is `overflow: clip`

Nextcloud 34 makes `#content` the app's mount parent a `position: fixed`, `overflow: clip`, `display: flex`
box of the viewport's height. `clip` means nothing scrolls and nothing is reachable, and no ancestor
established a scrolling region. Measured on the transaction form at a 1280×720 viewport:

| | |
|---|---|
| viewport | 1280 × 720 |
| `#content` | 662px tall, `overflow: clip`, `position: fixed` |
| `main.pettycash-shell` | 1041px of content |
| Save draft / Create / Cancel | at y = 925–959, inside the clipped box |
| `document.documentElement.scrollHeight` | 720 (nothing to scroll) |

Playwright's own log is the clearest statement of it:

```
locator resolved to <button data-test="transaction-save-draft" …>
attempting click action
  element is visible, enabled and stable
  scrolling into view if needed
  done scrolling
  element is outside of the viewport
  … 52 × retrying …
```

A purchaser could open the transaction form and then not save a draft or submit anything from it. Fixed in
`src/styles/app.scss` by making `#pettycash-app` the scroll region. `min-height: 0` there is load-bearing:
as a flex item its automatic minimum size is its content size, so without it the item is grown to its
content and then clipped — which is the bug. `overflow-x` is deliberately left alone so a genuine
horizontal overflow stays visible to FR-071's measurement rather than being hidden.

### 4. Six of seven journeys could not create a sheet — a spec defect, not a product one

`accountId` is required. One journey selected an account; the other six repeated the create-form steps
without it, which left the submit button permanently disabled by
`:disabled="sheetStore.loading || !isSubmittable"`. Each then timed out on the **next** line
(`create-transaction-btn`), so the message pointed away from the step that was actually missing.
Centralised into `createSheet()` / `openSheet()` helpers, and the sheet is now addressed by its title
rather than `:first-child` — the list is `created_at DESC` over a table that accumulates rows across runs,
so `:first-child` addressed whichever sheet happened to be newest rather than the one the test created.

### Two assertions in the suite were themselves wrong

- `toContainText('50,000')` — `formatMoney()` renders via `toLocaleString('fa-IR')`, so the cell reads
  `۵۰٬۰۰۰ IRR`. Hard-coding either spelling makes the E2E test a change-detector for a formatter that
  `tests/Frontend` already owns; the journey now asserts the row exists and carries the sheet's currency.
- `toContainText('Draft')` — `StatusBadge.vue` renders `t('pettycash', 'reviews.status.draft')` and
  **`l10n/fa.js` does not exist** (T119 owns the Persian catalog and is open), so `t()` returns the key and
  the cell reads `reviews.status.draft`. Asserting either `Draft` or the raw key would bake in the missing
  catalog, so the assertion now uses the locale-independent hook `StatusBadge` already emits,
  `data-testid="status-badge-draft"`.
- `toContainText('test-user')` expected a user that does not exist; the fixture account is `pettycash-e2e`.
  It sits inside the audit assertions, which remain blocked by T098.

## Why 237 green tests missed all three

Every frontend spec replaces `@nextcloud/vue` with hand-written stubs. **A stub cannot catch a defect in
the seam between the app and the stubbed library, because the stub is that seam** — the stub's `NcSelect`
emitted a string, and the stub's `NcNoteCard` rendered its children, so both library contracts appeared to
hold. Nothing asserted that the controls a requirement is performed *through* were on the page.

`tests/Frontend/Component/NextcloudVueContract.spec.ts` now mounts the **real** library. This required
`test.server.deps.inline: [/node_modules/]` in `vitest.config.ts`, because `@nextcloud/vue`'s chunks
`import('../assets/NcButton.css')` and Node's ESM loader refuses that with
`Unknown file extension ".css"`. It also needed a real `interceptors` object on the `@nextcloud/axios`
mock: `@nextcloud/files` runs `axios-retry` against the default instance at import time, and without it
`NcUploadPicker` — which `SheetDetailView` pulls in transitively — threw
`Cannot read properties of undefined (reading 'request')` with a stack trace pointing at `axios-retry`
rather than at this app.

**Mutation-verified**, per fix and not just per suite:

| Mutation | Result |
|---|---|
| `:reduce` removed from the sheet form's `NcSelect` | **2 of 6 fail** — `derives a scalar identifier from every option the sheet form offers`, `sends the account as a scalar identifier, not as the option object` |
| `<template #header>` reinstated in `SheetDetailView` | **1 of 6 fails** — `renders the sheet action bar that the purchaser journey depends on` |

The scroll fix has no jsdom gate and cannot have one: jsdom has no layout engine, and a declaration scan
would only prove the rule is spelled correctly. Its gate is the Playwright suite — which is precisely why
T171 still has to be finished rather than closed on the strength of the unit tests.

## What still blocks the other six journeys

All three are API-side and none was in the ledger.

### T326 — `GET /sheets/{sheetId}/transactions` does not exist

`appinfo/routes.php:22` declares only `POST` for that path and `contracts/ocs-api.yaml:430` declares only
`post:`. The frontend calls it (`src/stores/transactions.ts:48`) and gets:

```
405 Method Not Allowed        (empty body)
```

So `SheetDetailView.vue:201`'s `v-for="item in transactionStore.transactions"` iterates an array nothing
can fill: after `POST /sheets/{id}/transactions` returns **201**, the purchaser returns to a sheet whose
table is empty. That 405 is also the source of the `pettycash.error.network` alert that was on the page
throughout this work — the alert was reporting a real fault.

### T327 — `GET /sheets/{sheetId}` returns neither `transactions` nor `allowedActions`

```
top-level keys: [completedAt, createdAt, currency, id, ownerDisplayName, ownerId,
                 status, submittedAt, title, totals, transactionCount, version]
has transactions: False
```

`contracts/ocs-api.yaml:1125` **requires** both (`SheetDetail: allOf [SheetSummary, { allowedActions,
transactions }]`) and `src/types/api.ts:69` mirrors it. Because
`src/stores/sheets.ts:14` computes `canSubmit` as `status === 'OPEN' && (transactions?.length ?? 0) > 0`,
and `transactions` is `undefined` in every response the server can currently produce, **`canSubmit` is
permanently `false` and the Submit button is never in the DOM.** A purchaser can create a sheet, add a
draft and save it, and then has no way to submit it.

`grep -rn "allowedActions\|'transactions'" tests/` returns one backend hit —
`FinanceSettlementTest.php:662`, on a *transaction* detail — and **no test at all** for
`GET /sheets/{id}`. That absence is how it shipped.

### T087 — pre-existing, unchanged

The eleven `configuration#*` routes are registered and answer **500**
(`lib/Controller/ConfigurationController.php` does not exist), so the cost-centre and expense-type
dropdowns are empty and journeys 4–7 cannot select them. Already recorded on T087; T171 does not release
it.

### T098 — pre-existing, unchanged, and the two audit journeys are untouched

`[data-test="audit-event"]` exists nowhere in `src/`, `SheetDetailView.vue:257` renders a hardcoded
`<tr v-if="false">`, and there is no `GET /sheets/{sheetId}/audit` route — so this needs an endpoint, not
a binding. The assertions were **not** weakened, skipped, or deleted to make the task look finished.

## Known limitations

1. **T171 is not complete.** One journey green of seven. T326 and T327 must land, and T087 must, before the
   browser chain can be verified — and eight other tasks are gated on it.
2. **The scroll fix has no unit-level gate.** Only a browser can measure it, and only T171's suite does.
   A declaration-level check would prove the rule is spelled right, not that it works.
3. **The revision selector's options use `{ title, value }`.** `vue-select` renders `label`, so those
   options are blank in the dropdown. Found while fixing the other seven selects and left alone: it is
   T075's `TransactionDetailView`, not on T171's path. Worth recording on T075.
4. **`SheetListView` renders an open sheet twice** — once in `[data-test="open-sheets"]` and once in
   `[data-test="sheets"]`, because `openSheets` is a filter over the same array. The suite now needs
   `.first()` on title-scoped locators because of it. Whether the duplication is intended is a design
   question for T053, not something to settle inside a verification pass.
5. **The e2e suite is not self-cleaning.** Each run leaves its sheets behind for `pettycash-e2e`. The
   assertions are now order-independent, so this does not cause false results, but the table grows without
   bound. 57 stale sheets from earlier runs were removed once, scoped strictly to the e2e user and
   excluding the seeder's own `E2E_IDS` namespace.
6. **The environment was adjusted to get a clean baseline**, not just read: that one-time cleanup ran
   against the shared dev lab and is recorded here because it mutated data. Nothing else outside
   `pettycash-e2e` was touched, and no Docker lifecycle command was run.
