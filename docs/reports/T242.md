## T242 — Evidence upload raised a 500 on every request

`IRequest::getUploadedFile()` is documented to return the `$_FILES` element and
`Request::getUploadedFile()` returns `$this->files[$key]` verbatim, so in Nextcloud 34 the
call yields the raw per-field array, not an `OCP\Files\UploadedFile`. `EvidenceController::upload()`
annotated the result as a single `UploadedFile|null` and then called `getError()`,
`getContent()`, `getClientName()` and `getClientMimeType()` on it. The resulting
`Error: Call to a member function getError() on array` was raised inside `Dispatcher.php:165`,
which is *before* the action's own `try/catch`, so the `OcsErrorMapper` could not shape it and the
client received an unstructured HTTP 500.

New private helpers normalise the three shapes the request layer can hand back — the raw
`$_FILES` entry, an `UploadedFile` object, or a list of them — so the action no longer depends on
that difference.

The 100 MB ceiling is now checked from the **declared** size *before* the bytes are read into
memory, so an oversized upload is rejected rather than buffered. `EvidenceService::MAX_FILE_SIZE`
became public so the controller and the service share one limit, and a new
`OcsErrorMapper::payloadTooLarge()` emits 413 through the centralized mapper.

## T243 — Nextcloud 34 access-attribute compliance

All 24 `@NoAdminRequired` docblock annotations across 7 controllers were replaced with
`#[NoAdminRequired]`, with the import added to each file. Nextcloud 34 writes a log entry per
annotated method per request advising the attribute form; those entries had come to dominate the
app's request log.

## T244 — Invalid RED state in the purchaser-flow spec

`PurchaserFlow.spec.ts:411,418` called `.setFiles([...])`, which is not a member of `DOMWrapper` in
`@vue/test-utils` 2.4.6. Both assertions therefore died with a `TypeError` regardless of how the
uploader was implemented — not valid RED evidence under the `AGENTS.md` rules. Both now use the
`Object.defineProperty` + `trigger('change')` pattern already proven elsewhere in the same file.

While verifying T242 the OCS envelope helper in `PurchaserFlowControllerTest` was also corrected:
it asserted `ocs.meta.status === 'ok'` unconditionally, which is wrong for any non-2xx status.
`ManagementReviewControllerTest` already branched on `< 400`; the purchaser helper now matches it.
