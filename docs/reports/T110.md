## The three properties, and why one test cannot hold them

`contracts/exports.md` requires two things that read as one invariant from opposite ends: "the manifest
lists only files actually present in the archive", and the acceptance check "the manifest-to-file
mapping is complete". So the tests split by *direction of failure*:

1. **Manifest-to-file completeness** — a requested file whose bytes cannot be read is omitted from the
   archive **and** from the manifest, and recorded in `omitted` with a reason. A manifest that names a
   missing file is worse than no manifest, because it looks like evidence.
2. **Path safety** — `originalName` is user-controlled and a ZIP member name is interpreted by whatever
   extracts it. `ZipArchive::addFromString()` does not stop a traversing name being written.
3. **Refusal versus omission** — an unreadable file is a storage condition; a file over FR-074's 100 MB
   ceiling means the upload validation did not hold. The second is a refusal, because silently dropping
   evidence from a financial export is the failure mode FR-053 and FR-059 exist to prevent.

## The mutation that did not fail

Deleting the explicit separator-stripping in `safeBasename()` left all 34 tests green. The temptation is
to record that as "the line was redundant" and remove it. **It is not redundant, and the mutation is the
interesting result rather than a null one.**

`basename()` on Linux already removes `/`, so stripping `/` changes nothing — which is why the
traversal tests still passed. But `basename()` does **not** treat `\` as a separator, so a
backslash-bearing name reaches the member path intact. On Linux that is harmless; on a **Windows
extractor** `\` *is* a separator, and that is the platform where a traversing member name would actually
be extracted. The defence was real and simply had no test.

The fix was not to delete the line but to make it load-bearing: the hostile-filename test now also
asserts that no member path contains a backslash. Re-running the same mutation fails 2
(`..\..\windows\system32\config` and `C:\Windows\System32\evil.dll`).

Worth stating as the general lesson: a mutation that survives tells you something is unverified, and
"unverified" and "redundant" look identical from the outside. The cheap mistake is to delete the
defence and record a pass.

## One real defect the tests found

`sub/../../escape.pdf` became `sub .. .. escape.pdf` — replacing the separators with spaces left `..` as
a literal substring. Not traversable, since it is inside a single segment, but worth eliminating: an
extractor that checks member names for `..` by substring would mishandle a legitimately named file, and
a name containing `..` is a standing reminder that the input was hostile. Dot-runs are now collapsed to
`_`, and a name left with only separators and filler falls back to the evidence public id.

## Two design decisions

**The manifest is written by `CsvExporter`, not a second CSV writer.** Sheet titles and uploader display
names are user-controlled, so the manifest carries exactly the same formula-escaping duty as any other
export, and a second writer is a second place to get that wrong. This required giving
`CsvExporter::export()` an optional explicit-header argument: the manifest's columns are fixed by the
contract and must still be present when the archive turned out to be empty, which deriving the header
from the first row cannot do. A recipient must be able to tell "no evidence was in scope" from "the
export is broken".

**It does not implement the tabular `Exporter` port.** That port models `iterable<array> => string`, and
a ZIP with binary members is not tabular — its rows are a manifest *derived from* the archive, not the
input to it. Forcing the shape would mean smuggling a reader callback through an `iterable`. How the four
exporters compose is T111's decision, and inventing that shape here would be unrequested work.

## Deliberately not done

- **Not registered in the container.** No consumer until T111.
- **T103 is untouched.** It is the umbrella RED task for all four exporters plus transient cleanup and
  out-of-scope omission; this pass wrote focused per-exporter tests on the T237→T138 pattern, so a
  failure is attributable to a format. T103 remains open for XLSX and PDF.
- **Scope is not decided here.** "Evidence outside the requester's scope is omitted before the archive
  is built" is an authorization rule and belongs to the layer above; this class receives entries already
  in scope and cannot widen or narrow them.
