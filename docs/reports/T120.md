# T120 — partial: the FR-071 typography half

**Task**: T120 (US8) — **still open**; the typography half is complete
**Feature**: PettyCash V1 Core Workflow (`specs/001-pettycash-v1-core`)
**Date**: 2026-09-26

`tests/Frontend/typography.spec.ts` is **4/4 green**, from 42 declarations below FR-071's 12pt floor.

## What was wrong

Not one component's slip. The app's **type scale itself started below the requirement**: its smallest
steps were 12px, 13px and 14px (`0.75rem`, `0.875rem`, `0.9rem`), spread across 16 files — every
caption, meta line, table cell and status badge in the application. FR-071 requires ≥12pt, which is
16px, so the whole app was under the floor. T283 found this and deliberately left it red, recording
that `T120` owns the styling.

## What was done

The scale is now written down once, in `src/styles/app.scss`, as four custom properties on
`.pettycash-shell`:

| Token | Value | Use |
|---|---|---|
| `--font-size-floor` | `1rem` | body text, table cells, captions, meta lines |
| `--font-size-emphasis` | `1.125rem` | a value that must outrank the label beside it |
| `--font-size-section` | `1.25rem` | a section heading within a card |
| `--font-size-title` | `1.5rem` | the page title |

All 44 declarations read the tokens. The two-step pattern the components already used — a
de-emphasised 12px label beside an emphasised 14px value — became `1rem` beside `1.125rem`, so the
hierarchy survives the floor being raised underneath it. De-emphasis is now carried by colour and
weight; a "small caption" step is what put the app under the floor, and a reader with low vision is
the reader FR-071 is about.

## The gate had to get stronger, not weaker

Expressing the scale through tokens initially made the gate **fail**, because
`tests/Frontend/typography.spec.ts` reads declarations as written and could not resolve a reference.
Two options: forbid tokens, or teach the gate to resolve them.

Forbidding them was rejected. A gate that reports every `var(--font-size-floor)` pushes the next
author back to a literal in every component — which is how the same sub-floor size came to be written
out 42 times. The gate now resolves both spellings the app uses, SCSS variables and CSS custom
properties, collected across every stylesheet before any file is read, because a component's scoped
block reads a token the shell declares and neither file resolves alone.

## The gate is mutation-checked

Because the change made the gate more permissive in one dimension, each escape route was proven to
fail it:

| Mutation | Result |
|---|---|
| A scale token set below the floor (`--font-size-emphasis: 12px`) | **caught** — both reading components reported |
| A component restating a literal (`font-size: 12px`) | **caught** |
| A component referencing an undeclared token (`var(--not-declared)`) | **caught** |
| A component reading the scale through tokens | guarded by a dedicated assertion, so the scale cannot silently stop being load-bearing |

An earlier version of the fix was caught **not** biting: three of the four variables were declared but
unused, because the components still held literals. That is a real defect in the first attempt — the
scale would not have been single-sourced — and is why the tokens are now what the components read.
