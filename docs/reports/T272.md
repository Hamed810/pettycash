# T272 — the route guard, and why it is green instead of red

**Task**: T272 (complete)
**Feature**: PettyCash V1 Core Workflow (`specs/001-pettycash-v1-core`)
**Date**: 2026-09-27
**Pass**: Autopilot implementation pass 4 of 50

## What the task asked for

A structural test that parses every `['name' => '…#…']` entry in `appinfo/routes.php` and asserts the
named controller class exists and declares the named public action — because a route registered ahead of
its implementation answers HTTP 500, which is worse than an absent route since the contract says the
endpoint exists. The task also said the test "may legitimately stay red until T087, T112, and T096 land,
in which case it must be recorded as an expected-failure list owned by those task IDs rather than
deleted."

## The decision: the assertion is inverted

Fifteen declared routes still do not resolve, so the literal reading of the task produces a permanently
red test. That is not a guard. A test that is always red trains everyone to ignore it, and the day
someone skips it for being noisy is the day it stops protecting anything.

So the assertion is inverted: the test asserts the set of unresolved routes is **exactly** the
documented, task-owned `KNOWN_UNRESOLVED` list. That is strictly stronger than a red test, because it
fails in both directions:

- a route registered ahead of its implementation **adds** to the set → fails. This is the defect the
  file exists for.
- a task lands and resolves one of them → a **stale** entry remains → fails, prompting the entry's
  deletion in the same commit that marks the task `[X]`.

A stale entry is the quiet way a task-owned list stops being a guard, so it is asserted explicitly
rather than left to be noticed.

`testNoDeclaredRouteIsSilentlyUnresolvedOnceTheKnownListIsEmpty` is the belt to that braces: the day the
list empties, the file *becomes* a plain "every route resolves" gate with nothing further to edit here.
`testTheKnownUnresolvedListIsNotEmptySoTheGuardIsStillNeeded` exists so that transition is noticed
rather than discovered later.

## Two implementation problems worth recording

**Reflection cannot be used here.** The obvious implementation is `class_exists()` plus
`ReflectionClass`. It cannot work: `tests/bootstrap.php` deliberately does not bootstrap Nextcloud, so
autoloading a controller dies on its own `extends OCP\AppFramework\Controller` — three tests errored
with `Class "OCP\AppFramework\Controller" not found` before this was rewritten. That error is about the
*parent class*, long before the method under test is reached, so it says nothing useful.

The fix was to stop asking the runtime. This is a *structural* claim — does this file declare this
method, and is it public — and the source file is the authority for it. `methodVisibility()` reads
`token_get_all()` output, skipping attributes and modifiers to find the last visibility token, and
treating a method with no modifier as public because that is the language rule. It also keeps the test
free of a Nextcloud runtime, which is what lets it live in the fast suite.

**`nikic/php-parser` was available but not used.** It is present in `vendor/` as a *transitive*
dependency and is not declared in `composer.json`. Building a test on it would couple the suite to a
dependency the project does not claim, for no gain over `token_get_all()` on a question this simple.

| Routes | Owner |

Each entry names its owning task ID, and `testEveryKnownUnresolvedRouteNamesTheTaskThatOwnsIt` asserts
the format, so an entry cannot become an unowned allowance. Convergence Phase 38 re-verified all

that exists but is not public is *just as undispatchable* as a missing one, and an existence-only test
would have called it resolved.

## One extra assertion, deliberately scoped

`testTheControllerDirectoryHoldsNoUnroutedDuplicate` lists every `*Controller.php` that no route
references, and asserts the list is exactly `['QueueController', 'ReturnsController']` — T235's
subject. It does **not** decide T235; remove or route is still the maintainer's call, and this task did
not make it. What it does is make the set of unrouted controllers a fact in the suite rather than
something a reader has to remember, so the decision gets made against a list. If they are routed the
list shrinks; if they are removed it empties. Either way the list changes in the same change as the
decision, which is the property that keeps this from becoming another stale allowance.

## Limitations

- The test proves a declared route resolves to a public action in a file that exists. It does not prove
  the action behaves correctly, is authorized, or returns the contract's status codes. That is what the
  per-endpoint contract tests are for, and several of those endpoints do not exist yet.
- It cannot see a route declared in a way `require`-ing `routes.php` does not return, or a controller
  resolved through a nonstandard naming convention. Both would be a departure from the AppFramework
  convention this test encodes, which is the convention the rest of the app already follows.
- Psalm and `php-cs-fixer` remain unavailable for the reasons in `docs/reports/T237.md`.
