# T259 — Evidence deactivation and streaming reach the AppData store correctly

**Status**: Complete (one residual contract conflict recorded, not resolved)

## Task

Apply the T247 no-read-back rule to the two evidence read paths, which both returned HTTP 500.

## The recorded root cause was wrong

T259 attributed both 500s to the AppData read running on a connection that cannot see the
filecache row written by a still-open transaction — the failure T247 diagnosed for upload.

That was not it. The read was tested **inside and outside** a database transaction directly
against the real `AppDataEvidenceStore` in the container, and it failed in both cases. There was
no transaction involved. Two independent defects were actually responsible.

## Defect 1 — evidence keys were never resolvable on read

`putEvidence()` writes into nested folders and returns the full
`evidence/<transaction>/<revision>/<filename>` key. But `read()`, `deleteDraft()`, `exists()`, and
`getFileSize()` all passed that whole key to `getFile()` on the evidence folder, as if it were a
single filename. No key this class had ever written could resolve, so every read reported
`AppData file not found`.

Confirmed against the real store: `exists()` returned `false` and the read threw, outside any
transaction, for a file that was present on disk with a committed `filecache` row.

Fix: a new `findFile()` splits the key and walks the folders, dropping the leading `evidence`
segment because the walk already starts inside that folder. All four methods route through it.

## Defect 2 — the evidence update wrote columns that do not exist

`DbEvidenceRepository::save()`'s update branch set `updated_at` and `updated_by`.
`pettycash_evidence` has no such columns. The migration records
`uploaded_by`/`uploaded_at` and `deactivated_by`/`deactivated_at`/`deactivation_reason`, with no
update pair — an evidence row is only ever deactivated, and the deactivation columns are that
record.

Every deactivation therefore failed with:

```
SQLSTATE[42S22]: Column not found: 1054 Unknown column 'updated_at' in 'SET'
```

and the endpoint returned HTTP 500. Those two writes are removed.

## Residual failure left open deliberately

`testGetEvidenceContentReturns200WithStream` now passes its status assertion and fails on
content type:

```
Failed asserting that two strings are identical.
--- Expected
+++ Actual
-'application/octet-stream'
+'application/pdf'
```

`contracts/ocs-api.yaml:661` declares `application/octet-stream` for
`GET /evidence/{id}/content`. The controller serves the stored `media_type`, and FR-060 requires
that authorized users be able to *preview* supported evidence. Those two cannot both hold:
`application/octet-stream` forces a download rather than a preview.

This is a contradiction between an approved contract and a functional requirement. Constitution
Governance requires work to stop long enough to reconcile a conflict in the authoritative artifact
rather than choosing silently, so it is recorded for convergence instead of being resolved here.
No task in `tasks.md` currently owns it.
