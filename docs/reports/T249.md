# T249 — Widen `pc_transactions.current_status` so every workflow state is persistable

**Status**: Complete
**Feature**: PettyCash V1 Core Workflow (`specs/001-pettycash-v1-core`)
**Task**: T249 (Phase 25, CRITICAL) — unblocked T221
**Date**: 2026-09-25

## Problem

`lib/Migration/Version010100Date20260920000000.php:36` declared
`pc_transactions.current_status` as `Types::STRING` with `length => 24`, but
`lib/Domain/Workflow/TransactionStatus.php` defines two longer backing values:

| Value | Characters | Column allowed |
|---|---|---|
| `AWAITING_COST_CENTER_REVIEW` | 27 | 24 |
| `AWAITING_PURCHASER_CORRECTION` | 29 | 24 |

Seeding a submitted transaction failed immediately with
`SQLSTATE[22001]: String data, right truncated: 1406 Data too long for column 'current_status'`.
The two states that matter most — a sheet entering formal cost-center review, and a transaction
returned to the purchaser — could not be persisted at all, so the US1 → US2 → US4 path was
unreachable regardless of application code.

## Implementation notes

The first attempt used `Table::changeColumn($name, Types::STRING, ['length' => 32])`. That
signature does not exist in the bundled Doctrine DBAL: `changeColumn()` is
`($name, array $options)` and is deprecated in favour of `modifyColumn()`. The upgrade aborted
with a `TypeError` and left Nextcloud in maintenance mode. The canonical Nextcloud 34 form, taken
from `core/Migrations/Version28000Date20240828142927.php`, is:

```php
$schema->getTable('pc_transactions')->modifyColumn('current_status', [
    'notnull' => true,
    'length' => 32,
]);
```

Maintenance mode was restored to disabled and `occ status` reports `needsDbUpgrade: false`.

### Portability (FR-077 / research.md Decision 16)

`VARCHAR(32)` keeps the `pc_tx_sheet_state` index within every declared backend's limits: at
utf8mb4 the widest key is `8 + (24 * 4) + (32 * 4) = 232` bytes, far below InnoDB's 3072-byte
limit, and PostgreSQL and SQLite impose no such prefix limit. The index keeps the same columns
in the same order, so no index change is required. `npm run check:portability` reports
`OK — no vendor-specific constructs`.

## Limitations

- The container runs `opcache` with `revalidate_freq => 60`, so a PHP edit can take up to a minute
  to reach live HTTP.
- Raising the app version to `1.3.0` made Nextcloud require an upgrade; `occ upgrade` applied
  core's (already current) migrations and the new PettyCash migration, and maintenance mode was
  turned back off afterwards.
- The regression guard reads the migration sources rather than the live schema, so it runs in the
  standard suite without a database. A migration test that actually executes migrations against
  the live schema is still open under T254.
