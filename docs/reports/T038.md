## Verification Details

### EvidenceService Implementation
| Operation | Method | Features |
|-----------|--------|----------|
| Upload | `uploadEvidence()` | 100 MB limit, opaque key, SHA256 checksum, metadata persistence |
| Delete Draft | `deleteDraftEvidence()` | Owner-scoped, deactivation instead of deletion |
| Read | `getEvidence()` | Owner-scoped access control |
| List | `listEvidence()` | By transaction, active-only filter |
| Content | `readEvidenceContent()` | Stream evidence bytes |
| Exists | `evidenceExists()` | Check file presence |
| File Size | `getEvidenceFileSize()` | Size validation |

### Compliance with Requirements
| Requirement | Implementation |
|-------------|----------------|
| 100 MB max file size (FR-074) | Enforced in `uploadEvidence()` and `AppDataEvidenceStore` |
| No advanced evidence restrictions (FR-030) | All authorized viewers can access; no classification/redaction |
| Opaque key structure | `evidence/<transaction-uuid>/<revision>/<filename>` via `AppDataEvidenceStore` |
| Checksums | SHA256 via `AppDataEvidenceStore::getChecksum()` |
| Safe filenames | Sanitization in `AppDataEvidenceStore::sanitizeFilename()` |
| Draft-delete compensation | `deleteDraftEvidence()` deletes file + deactivates metadata |

### Architecture Compliance
- Service in **Application layer**
- Uses **Application Ports** (PrivateFileStore, CurrentUser, EvidenceRepository)
- No business logic in adapter - pure orchestration
- Owner-scoped access via `CurrentUser` port
