# T268 — The duplicate command-result port is gone, and the layer boundary is now watched

**Status:** Complete (1 pre-existing failure unchanged)

## Task

Delete the unused duplicate port `lib/Domain/Command/Repository/CommandResultRepository.php` and its
half of `DbCommandResultRepository`'s `implements` clause, keeping
`lib/Application/Command/CommandResultRepository.php` as the single port. The task's reasoning was that
the domain copy is byte-for-byte equivalent to the application port yet imports
`OCA\PettyCash\Application\Command\CommandResult`, making the innermost layer depend on the layer above
it — which `plan.md` forbids and which Constitution III requires to stay separable.

## The part that is not a deletion

A two-line deletion has no test. Nothing about deleting an unused interface can fail — and that is
exactly the problem: the file was there because nothing watched it, and deleting it because nothing
watched it leaves the next one equally unwatched.

So the deliverable is the **property**, not the removal. `LayerBoundaryTest` scans `lib/Domain/` and
fails on any `use OCA\PettyCash\{Application,Infrastructure}\…`, and it asserts
`CommandResultRepository` is declared exactly once. Both would have failed before this task and both
pass now, and — the reason this is worth doing — **both will fail again** if a duplicate port reappears
in any location, which no reviewer has to notice by reading two files side by side.

## RED state, and the two bugs it exposed in my own test

The first run failed **three** of four tests, and two of those failures were not the defect under test.
Both were found by taking the RED seriously rather than by reading the assertion:

1. **The messages were unusable.** Every violation read
   `tests/Unit/Architecture/../../../lib/Domain/Command/…`. Technically true, practically useless — a
   message is for someone who has to open the file. `relative()` now `realpath`s both sides.
2. **The sanity check failed against a working scan.** It compared a repo-relative anchor against the
   iterator's absolute paths. The scan was fine; the assertion was wrong, and it was wrong in the
   direction of being *unreliable*, which is the worst direction for the one test whose job is to prove
   the others are not vacuous.

Neither would have been found by a green run. Both are the reason the third test exists at all.

## What the scan asserts, and what it deliberately does not

- `testTheDomainLayerHasNoOutwardDependency` — the boundary, with the offending file and the imported
  class named.
- `testTheScanActuallySeesTheDomainLayer` — that a *known* Domain file is in the scan. A directory
  test that finds nothing to look at passes forever; this is what stops an empty glob, a renamed root
  or a moved directory from being reported as a clean boundary.
- `testCommandResultRepositoryIsDeclaredExactlyOnce` — the count and the location, so a deletion that
  left the *domain* copy behind fails.
- `testTheDeclaredLayerOrderIsTheOneTheRuleDependsOn` — `LAYER_ORDER` itself. Every comparison is
  `array_search` over that table, so a table with `Domain` last would make the rule "nothing is above
  Domain" and the scan would pass over a real violation while saying nothing. The rule and the
  assertion are only as good as the order they share, and the order is data in a test file like any
  other.
- `testEveryConsumerUsesTheApplicationLayerPort` — the surviving import. Asserted separately from the
  count because "declared once" and "declared in the right place" are different claims.

Only the Domain → upward rule is asserted. `Application` may reach `Domain` and `Infrastructure` may
reach both, and that is a larger piece of work: `lib/Application/` imports `OCA\Server` and other
Nextcloud services in places, and deciding where the line falls is a design question rather than a
scan's question. Stated here so the omission is a decision on the record rather than an oversight.

## Mutation-proven, three times

| Mutation | Result |
|---|---|
| A Domain port is re-introduced, importing `Application` | **1 fail** |
| `LAYER_ORDER` reordered so `Domain` is last — the rule inverts | **1 fail** |
| The scan is pointed at a directory that does not exist | **3 fail** |

The second is the one worth keeping. It is not a code defect anyone would introduce; it is the test's
own supporting data being wrong, which is the class of error that makes a boundary test *look* like
coverage. The third proves the sanity check has teeth: an empty scan is now a failure rather than a
clean bill of health.

## Known limitations

- **The other three layer edges are unasserted**, deliberately. See above.
- **The scan reads source, not the autoloader.** A class reached without an import — a fully-qualified
  inline reference, say — is invisible to it. That is a real limitation of the approach rather than a
  gap in it, and it is stated rather than hidden: the rule it enforces is about *declared* dependency.
- **T268 changed no behaviour**, so it adds no coverage of its own beyond the boundary. The suite total
  moving 741 → 745 is the four new architecture tests and nothing else.
- T275, T304, T309 and T312–T316 remain open. T309's checkbox is still stale in the way T308 and T311
  both recorded.
