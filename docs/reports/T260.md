`dropTable`, `renameTable`, and `renameIndex` appear nowhere in the migrations.

## T262 — approval-gated development-only reset (executed)

Explicitly approved by the maintainer with one added safety constraint: produce and verify an
explicit allowlist of the exact V1 development tables, and never delete by wildcard/prefix, because
the live database holds both the V1 development tables and 11 unrelated prototype tables under the
same `oc_pc_` prefix.

### Allowlist derivation and verification

The allowlist was **derived from the rewritten migrations**, not hand-written: every
`createTable('…')` in `lib/Migration/Version*.php` yields the 15 logical tables, and the pre-rename
physical names are those same 15 with the `pc_` prefix that T260 replaced. The live schema was then
read back and partitioned by set membership, which makes the split provable rather than guessed.

| | Count | Basis |
|---|---|---|
| ALLOWLIST — V1 development tables replaced by T260/T261 | 15 | derived from the migrations, intersected with the live schema |
| DENY LIST — prototype tables that must not be touched | 11 | live `oc_pc_*` tables that are **not** in the migration-derived set |
| `allowlist ∩ deny-list` | **0** | disjoint |
| Live `oc_pc_*` total | 26 | 15 + 11, fully accounted for |

Allowlist: `oc_pc_currencies`, `oc_pc_cost_centers`, `oc_pc_expense_types`,
`oc_pc_role_assignments`, `oc_pc_accounts`, `oc_pc_account_movements`, `oc_pc_sheets`,

`oc_pc_evidence_links`, `oc_pc_transaction_audit`, `oc_pc_configuration_audit`,

Deny list (left untouched): `oc_pc_customers`, `oc_pc_emp_rates`, `oc_pc_license_state`,

### Execution

Deletion used explicit, individually-named `DROP TABLE IF EXISTS` statements with each identifier
validated against `/^[a-z0-9_]+$/` before use, after asserting the engine is MySQL/MariaDB and that

rewritten baseline was then executed through the app-scoped migration service
(`\OC\DB\MigrationService('pettycash', …)->migrate()`), which reported the 4 available versions as
unmigrated and ran exactly those.

## Verification detail: the collision that motivated the namespace

Inspecting the live schema before the reset found **26 `oc_pc_*` tables and zero `pettycash_*`**.
Fifteen of them were the V1 tables under the instance prefix — `oc_pc_currencies`, `oc_pc_sheets`,
`oc_pc_transactions`, and so on — colliding by name with the 11 unrelated prototype tables sharing
the same prefix. This is direct evidence that the provisional `pc_` prefix was never
collision-resistant, and it is the concrete justification recorded in T260 and in `research.md`
Decision 4.
