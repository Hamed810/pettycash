# T333 — Bind the five filters `contracts/ocs-api.yaml` declares on `GET /sheets`

**Status:** delivered
**Task:** `specs/001-pettycash-v1-core/tasks.md` T333 (Phase 55)
**Date:** 2026-10-04
**Layers touched:** Presentation (`lib/Controller/`), Application (`lib/Application/Expense/`),

## What the task asked for

FR-064's status / date / currency / creator filtering on `GET /sheets` had no implementation and no
owner. `contracts/ocs-api.yaml:332-346` declares `status`, `ownerId`, `currency`, `from` and `to`, and
the action bound only `page` and `pageSize`. Two further requirements: decide filter-then-count rather
than count-then-filter (so `total` means "matching records"), and refuse an unrecognised filter value
with 422 rather than ignoring it.

## What was actually there on arrival

The production half already existed in the working tree, uncommitted and never run: `SheetListFilter`,
`SheetListFilterFactory`, the five new `index()` parameters, and the filter threaded through both
`findByOwnerUid()` and `countByOwnerUid()`. So the task's `(missing)` annotation was already stale, and
T332's note that `countByOwnerUid()` took a `$status` "for predicate parity, not because a caller needs
it" was right in letter and wrong in spirit — the caller existed and had never been exercised.

The baseline was **RED with four errors**, so this task was finished, not started.

a fatal: the half that was written had never been run.

## The missing half: the transport

The round-trip scenario's own docblock had already scoped itself out of the transport:

> It does not bind the query parameters through HTTP, so the transport half — that `status`, `currency`,
> `from` and `to` arrive under those names at all, and that an unrecognised value is refused — is
> measured by the contract suite.

The contract suite had no such test. `tests/Contract/Controller/SheetListFilterContractTest.php` is new:
**20 tests / 1047 assertions**, covering all five declared filters (every `SheetStatus` case, not one
hand-picked value), seven refusal cases, and `ownerId` as scope.

## Two decisions worth keeping

**Every assertion is relative to the endpoint's own unfiltered answer.** The acting user already holds
261 sheets on this shared instance, across many days, so any absolute count is a claim about the lab's
history. A narrowing — a strict subset of the unfiltered page set — is the only comparison an ignored
filter cannot satisfy, because a discarded filter returns the baseline verbatim. The first test states
the precondition (more than one sheet, status and currency) explicitly, because a facet measured against
a one-valued baseline passes against an endpoint that filters nothing.

**The end-of-day reading is asserted as containment.** `from=today` selects exactly the sheets created
today, so a `to` bound read as midnight makes the two results *disjoint*. The assertion is that `to=today`
contains everything `from=today` contains. An "excludes yesterday" assertion passes against the midnight
reading; this one does not.

An earlier draft asserted `from=today == baseline total` and failed `18 is identical to 261`. The
narrowing was correct — 243 sheets were created on earlier days — and the assertion was not. That is why
the remaining date assertions are stated as disjointness: `SheetSummary` carries no creation date, so
"yesterday matches nothing" is not expressible without inventing one.

`ownerId` is answered as **scope, not predicate** — FR-064 resolves "creator" to the sheet's owner, so
naming the caller is a no-op and naming anybody else is a 403. A refused answer and an empty page are
distinguishable; an ignored filter is not.

## Blast radius, by reference analysis

`findByOwnerUid()` has three production callers; the two outside this task both predate it and both had
to be inspected rather than assumed:

- `DashboardController::figures()` (`:183`) passes `new SheetListFilter(SheetStatus::Open)` — required,
  since the figure *is* "open sheets" and an unnarrowed read would count every sheet the caller owns.
- `ReportController::sheetsReport()` (`:227`) passes `null` — correct, not a missed filter. `status` is a
  *column* in those rows and the report narrows via `ReportFilterFactory`'s own vocabulary; a sheet
  filter there would hide rows the report exists to show.

`SheetService::listSheets()` is the single production caller of `countByOwnerUid()` and hands it the same
filter object the read used — which is what makes filter-then-count structural rather than a convention
each repository has to remember.

Established with Serena `find_referencing_symbols`. Recorded because "the suite is green" is a weaker
claim than "every caller was inspected".

## Known limitations, deliberately not widened

- **No filter UI and no pager on the sheet list.** `SheetListView.vue` calls `loadSheets()` with no
  arguments, so FR-064's four facets are reachable only by hand-editing the query string. T332 recorded
  the same absence independently; the task named `lib/Controller/SheetController.php` and
  `contracts/ocs-api.yaml`, and the configuration UI is T088.
- **`GET /accounts`' `active` parameter**, named in the task entry, remains unbound — a second endpoint's
  defect.
- **`countByOwnerUid()` is a second query per list request**, the opposite trade from
  `AccountService::listMovements()`'s deliberate read-once. Filter-then-count has no single-query form
  that stays correct.
