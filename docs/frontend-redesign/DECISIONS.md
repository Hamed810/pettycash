### D-022 — Receipt timing and single-form creation directive (Accepted 2026-10-23)

- **Status:** Accepted. The product owner approved `BE-CR-004` and the receipt/creation slice on 2026-10-23.
- **Decision:** Saving an editable transaction never requires a receipt. The create form MUST allow the purchaser to select receipts before the first save and uploads them after the transaction exists through the existing evidence endpoint. Sheet submission and correction resubmission require at least one active receipt only when the active expense type's current `evidence_required` is true; a receipt-exempt transaction is not refused. The payload exposes server-derived `evidenceRequired`, and a `422` names every offending transaction. A debug-gated development fixture creates sheets with 25, 30, 35, and 40 transactions.
- **Scope:** 001 FR-089–FR-092 and SC-017; 001 `T431`–`T435`; 005 `T053`–`T063`; `contracts/ocs-api.yaml` and `contracts/workflow.md` only for the receipt rule, `evidenceRequired`, and the per-transaction `422`; `ADR-007`.
- **Relationship to D-018/D-021:** D-018 is amended **only** for `BE-CR-004`; `BE-CR-001`, `002`, `003`, `005`, and `006` remain blocked. D-021's frontend authorization remains in force. D-019's Git approval requirement remains in force; this directive authorizes no Git write and no other Batch B card.
- **Architecture:** `docs/decisions/ADR-007-pre-save-receipt-attachment.md` records the client-side staging choice and the rejected alternatives (pre-transaction upload endpoint, auto-created draft, receipt-on-save, snapshot-at-creation, frontend-only enforcement).
- **Implementation status (2026-10-24):** **DONE_VERIFIED (technical).** The backend is recorded as 001 `T431`–`T435`; the frontend, fixtures, and acceptance evidence are 005 `T044` and `T053`–`T063`. ## روش تغییر تصمیم / Decision change control

**فارسی:** برای تغییر یک تصمیم مصوب، ابتدا دلیل، گزینه‌ها، آثار بر Scope/هزینه/سازگاری/تست و نام تصمیم قبلی ثبت شود. سپس مالک محصول آن را صریحاً تأیید کند. رکورد قبلی حذف نشود؛ وضعیت آن `Superseded` و شناسه تصمیم جایگزین اضافه شود. بدون چنین روندی هیچ Agent حق تعبیر مجدد مصوبات را ندارد.

**English:** To change an accepted decision, record the rationale, alternatives, effects on scope/cost/compatibility/testing, and the prior decision ID. Obtain explicit product-owner approval. Preserve the old entry as `Superseded` with a replacement reference; no agent may silently reinterpret prior approvals.
